# Review: compressible compose body-editor min (clipped Send footer fix)

## Bug
Reply composer clipped its bottom row (quote "…" pill + attach/format/Send
footer) when a reply had extra address rows (visible Cc) plus a long authored
body. Root cause: `ComposeBodyLayout.editorHeights` returned `min == max`
(rigid, content-sized up to `collapsedCap` 320) in the collapsed-quote branch,
while the compose card itself is fixed-height (`ContentView.composeChrome`,
inline ≤460pt / floating ≤500pt) with `topLeading` alignment + `clipShape`.
Un-compressible content taller than the card ⇒ footer clipped off-card.

## Fix reviewed
`Sources/MishMail/Support/ComposeBodyLayout.swift` collapsed-quote branch:
`return (h, h)` → `return (Swift.min(h, emptyFloor), h)`.
- Empty/short drafts: `h == emptyFloor` ⇒ min == max == 100, unchanged (no
  first-keystroke snap).
- Longer drafts: min 100, max hugs content up to 320 — the fixed card can
  compress the editor (NSTextView scrolls internally) and the pill + Send row
  stay on-screen.
- No-quote branch untouched (already flexible min).
- No `layoutPriority` added: trailing `Spacer(minLength: 0)` compresses first,
  so the hug behavior in the short case is preserved.

## Tests
`ComposeBodyLayoutTests` updated: rigid-min assertions replaced; new coverage
for long-body cap (min == emptyFloor, max == collapsedCap), medium body
(min == emptyFloor, max == raw), and empty-floor unchanged.

`make test`: **Executed 1337 tests, 5 skipped, 0 failures.**

## Findings
- Correctness: matches the diagnosed root cause; minimal blast radius (one
  return + docs + tests). No unrequested changes.
- Nit (non-blocking): stray trailing blank lines added at EOF of both files
  and one extra blank line inside the test class.
