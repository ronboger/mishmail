# Review: Priority section max-count cap ("Pin at most")

Task: "i'd also like to just have a number of emails i can choose to pin,
ie max 10. i think gmail has something like this."

## Design

A count cap composing with the recency window: "Pin at most" picker — 5 /
10 / 25 conversations / No limit, default 10
(@AppStorage "priorityMaxCount", 0 = no limit). Input is date-sorted
newest-first, so the cap keeps the newest N qualifying threads; overflow
drops to its chronological spot in the date sections. VIP pins never
consume or respect the cap (may push the section past N), matching the
window exemption.

## Change (commit 2efaa45)

- PrioritySplit: `cap(_:)` normalizer (<=0 → nil); partition gains
  `maxCount: Int?`; qualifying non-VIP threads enter priority only while
  under the cap, otherwise go to rest in order. qualifies unchanged.
- SettingsView: "Pin at most" Picker below "Only pin recent mail"; footer
  sentence added.
- ThreadListView: reads the setting, passes maxCount, onChange added.
- MailStore.captureStarNavAnchor: conservative extra skip — when the cap
  is full, the focused thread is not VIP-exempt, and its lastDate is older
  than the oldest resolvable Priority-section row, starring won't visibly
  hoist, so no scroll/nav hold is captured. Unresolvable section ids fall
  back to current behavior. advanceForPriorityUnstar deliberately
  unchanged (in-section rows already qualified; leaving is cap-agnostic).
