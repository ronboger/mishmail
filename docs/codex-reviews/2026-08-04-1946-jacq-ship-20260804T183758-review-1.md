# Review: category-hide starred hoist + Categories popover anchor

Task: "when i go from showing to not showing updates in the inbox, it all of
the sudden shows more starred mail. also the checkboxes thing moves to the
right a bit and i'd prefer it stayed in place."

## Diagnosis (verified live against the real inbox)

1. **More starred mail after hiding Updates.** The list is paged
   (ThreadListPaging.pageSize = 100) and starred threads deliberately pin
   through category hides (CategoryHide.apply). Adding Updates to the hide
   set thins each day's rows, so page 1's date window deepened from ~Jul 29
   to ~Jun 1; months-old starred threads in hidden categories (LastPass,
   Partners, Lilly) newly loaded, and PrioritySplit hoisted them into the
   pinned Priority section at the very top. Reproduced: toggling the hide
   added/removed exactly those four June rows in Priority.
2. **"Checkboxes thing" shifting right.** The Categories popover (the 2×2
   grid of category checkbox pills) was anchored to the chip's default
   bounds-center. Toggling a pill grows the chip title ("…, Social" →
   "…, Social, Updates"), widening the chip and sliding the open popover
   ~20px right. Reproduced on the pre-fix build.

## Fix (commits fa4db54, 26d23b8)

- PrioritySplit.qualifies/partition gain `hiddenCategories`; starred /
  IMPORTANT threads in a hidden category are no longer hoisted into Priority
  (they keep their chronological spot; CategoryHide pin-through untouched).
  VIP pins unaffected. Membership reuses StarStickiness.isInHiddenCategory
  so semantics match the SQL exactly.
- MailStore.effectiveCategoryHide exposed (internal) and passed from
  ThreadListView.recomputeLayout; added onChange(of: effectiveCategoryHide)
  so the split recomputes even when the loaded thread set is identical
  (review finding from pass 1 — Grok fixed in rescue commit 26d23b8).
- Categories popover anchored with attachmentAnchor: .point(.bottomLeading)
  so it stays put while the chip grows rightward.
