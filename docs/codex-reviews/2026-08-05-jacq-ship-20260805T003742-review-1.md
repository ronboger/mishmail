# Review: starred threads always hoist into Priority

Task: "the starred email prioritization is kinda weird. there are starred
emails that aren't displaying up top. diagnose, decide on what is most
ergonomic behavior, and fix."

## Diagnosis

Yesterday's merge 42c331f (review record
2026-08-04-1946-jacq-ship-20260804T183758-review-1.md) suppressed the
Priority hoist for starred AND IMPORTANT threads sitting in a hidden
category. It was aimed at months-old starred promo threads flooding
Priority when a category hide deepened the paging window, but it also
demoted freshly starred mail: with Forums/Promotions/Social hidden, a
starred Forums thread (Ian's cryo-EM bootcamp email, Aug 4) pinned through
chronologically in "Yesterday" instead of appearing in the Priority
section. Same for other starred rows in "Last 7 days".

## Ergonomic decision

A manual star is the user's strongest explicit signal and should always
hoist into Priority regardless of category hides. The hidden-category
suppression is kept only for the auto-applied Gmail IMPORTANT label
(.starredImportant mode, threads not starred) — the noisy, non-explicit
signal that yesterday's complaint was really about containing. Old starred
threads sort to the bottom of the (date-ordered) Priority section.

## Change (commit fc0bf75)

- PrioritySplit.qualifies: `.starred` returns `thread.isStarred`
  unconditionally; `.starredImportant` returns true for starred, and only
  applies the hidden-category check to IMPORTANT-only threads. VIP / .off /
  .vips unchanged. hiddenCategories plumbing retained (still needed for
  IMPORTANT).
- Doc comments on qualifies/hiddenCategories and
  MailStore.effectiveCategoryHide updated to the new semantics.
- Tests: four starred-in-hidden tests flipped to expect hoist and widened
  to cover both modes (promo/social denorm flags and updates/forums
  labelIds); IMPORTANT-only hidden = no hoist kept; new
  testImportantOnlyInNonHiddenCategoryIsHoisted; VIP-in-hidden and
  empty-hide-set cases unchanged.
